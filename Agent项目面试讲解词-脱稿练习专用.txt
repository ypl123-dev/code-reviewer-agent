第一部分：项目介绍（2分钟，开场必讲）
============================================================

【开场白】

"我做了一个基于 SpringAI 的智能代码审查 Agent 项目。

核心场景是：开发者在 Gitea 上提交 Pull Request 后，系统自动拉取代码差异，通过大模型多维度审查，然后把审查结果作为评论回写到 PR 上。

技术栈是 Spring Boot 3.3.5 + SpringAI 1.0.0 GA + DeepSeek 大模型。"

【项目价值】

"做这个项目的初衷是，传统代码审查依赖人工，效率低且容易遗漏。
我用 AI Agent 的方式，让大模型能够自主调用工具、查询团队规范、
检索历史 Bug，给出更专业的审查意见。"

【三个核心亮点】

"这个项目有三个核心亮点：

第一是 Advisor 责任链，用洋葱模型把日志、记忆、敏感词过滤、
Token 截断等横切关注点解耦，类似 Spring Interceptor 的设计。

第二是 Function Calling，定义了 4 个工具让大模型自主决策调用，
比如看到 SQL 拼接会主动查安全规范，这是 Agent 和普通聊天机器人的核心区别。

第三是优雅降级架构，所有外部依赖都通过 ObjectProvider 可选注入，
dev 模式零依赖启动，不需要 Redis、RabbitMQ、PgVector 也能跑。"


============================================================
第二部分：完整流程讲解（3分钟，面试官问"流程是什么"时讲）
============================================================

【整体流程】

"整个流程分为 6 步：

第 1 步：开发者在 Gitea 创建 PR，Gitea 通过 Webhook 通知我的系统。

第 2 步：我的 WebhookController 接收通知，先做签名校验，
然后判断是同步处理还是投递到 RabbitMQ 异步处理。

第 3 步：调用 GiteaService 的 fetchPrDiff 方法，通过 Gitea REST API
拉取这个 PR 的代码差异，返回的是 unified diff 格式的文本。

第 4 步：把 diff 交给 DiffChunker 做三级分
